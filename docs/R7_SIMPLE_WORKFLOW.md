# R7 簡化流程與真機驗證

此版本取代 R6 的 App 內 AI 與日曆瀏覽設計。使用者已選擇「儲存記事後開啟原廠時鐘，日期由我在原廠畫面核對」。手機上的 Gemini 由使用者直接操作，本 App 不與 Gemini 連線。

## 自動化範圍

| 操作 | R7 行為 | 使用者核對 |
| --- | --- | --- |
| 填記事 | 名稱、內容、完整日期、時間存於 Junba | 表單及記事卡顯示完整日期時間 |
| 交給原廠 | `ACTION_SET_ALARM` 傳時、分與名稱／日期文字／內容，`EXTRA_SKIP_UI=false` | 原廠是否接收、實際日期時間、最後儲存 |
| 完整年月日 | Android 公開介面無對應欄位 | 在原廠選日期；名稱日期不代表設定已完成 |
| 編輯 | 更新同一筆記事；停用該筆舊 Junba 排程 | 原廠舊項目要另外修改或刪除；重送先提醒可能重複 |
| 刪除 | 刪 Junba 記事及該筆舊 Junba 排程 | 原廠已建鬧鐘須到原廠刪除 |
| 開原廠 | `ACTION_SHOW_ALARMS` 顯示鬧鐘清單 | Android 無可依 Junba ID 指定原廠項目／確認儲存／可靠直接刪除的介面 |
| 日曆提醒 | 實際 Google 日曆通知到達後，Junba 提交約 1 秒後的 AlarmManager 響鈴 | 通知存取與精確鬧鐘授權、來源通知、背景／音量設定 |

記事先成功寫入才開原廠。開啟失敗仍保留記事，可重試；新記事不偷偷另排 Junba 鬧鐘。原廠請求紀錄只記待核對，不當作成功證據。新記事限制未來日期時間；遇到夏令時間不存在／重複的時間要求重選，避免無聲選錯。

## 舊資料延續

- 保持 package、`junba.notes` 與 `native_links`，編輯保留不認識的 JSON 欄位，不一次重寫全部舊記事格式。
- 新記事用 `remind=false`、`ahead=0`、不重複；既有每日／每週／每月 Junba 記事繼續重排程，只有該筆編輯儲存時才停用。
- 舊日曆鏡像只依本機快取取消 PendingIntent，不讀 CalendarProvider、不改 Google 活動；舊快取保留。接收器也拒絕已退役的鏡像事件。
- 移除 AI 程式碼及 INTERNET／READ_CALENDAR 權限；舊加密 Key 不再讀取，未主動清除舊私有資料。
- 草稿包含原記事 ID、名稱、內容、日期與去重 token；繼續編輯草稿不另建一筆。切換記事先提示是否捨棄草稿。
- 刪除寫入成功後才取消舊排程；即使系統取消失敗，接收器也會拒絕已刪除／停用的舊記事。損壞的記事 JSON 不用空陣列覆寫。
- 備份只涵蓋記事／原廠請求紀錄，須寫入後重新讀回比對才報成功。不含原廠資料，未提供自動無損跨簽章移轉，禁止自動解除安裝。

## 日曆通知限制

只接受 Google 日曆包名，先排除其他 App 才讀文字。忽略群組摘要、持續通知、非 event／reminder 分類（未分類通知允許）、超過 2 分鐘舊通知與時間異常通知。既有通知不在授權時重播。

去重只存通知 key 的 SHA-256、來源發布時間與提交排程時間，最多 64 筆／7 天，不存活動文字。相同發布時間、來源 FLAG_ONLY_ALERT_ONCE 的更新與 30 秒內更新不再觸發。通知被移除會清除該 key 並取消尚未觸發的 1 秒排程；若來源持續共用同一通知且不移除，部分更新可能被視為重複，須真機確認。停用後取消已知待觸發排程，接收器也檢查開關。

Junba 播放的是系統預設 ALARM 鈴聲，最多 2 分鐘，可停止／5 分鐘後提醒。不保證繞過勿擾、靜音或省電限制。設定中的 5 秒測試只驗證 Junba 手動啟動聲音，不能取代日曆端到端測試。此連動不會建立原廠時鐘項目，原日曆通知可能也發聲。

## vivo 真機驗證清單（尚未執行）

1. 新建名稱「測試吃藥」、內容、明日指定時間；保存後確認原廠帶入的名稱與時分，手動核對日期並儲存，返回後記事仍在。
2. 測試下週、跨月、跨年日期；確認沒有只看到名稱日期就誤認原廠日期正確。若時鐘沒有顯示設定頁，從原廠鬧鐘清單開啟核對。
3. 輸入一半返回、重新開 App、旋轉畫面，確認草稿仍可繼續；編輯草稿儲存後記事總數不增加。快速點兩次儲存只新增一次。
4. 取消原廠建立、原廠不支援 Intent、拒絕權限時，記事保留且不宣稱建立成功。重送提示可能重複。
5. 編輯／刪除記事前後檢查原廠項目：必須由使用者另外處理。舊 Junba 排程只在該筆編輯或刪除時停用。
6. 日曆連動預設關閉。啟用三項權限，以 Google 日曆建立幾分鐘後活動及提前提醒，測試亮屏、鎖屏、背景、省電、勿擾、重新開機後收到通知是否響。其他 App 通知不得響。
7. 測試 Google 日曆摘要／更新、同時多活動、重複通知，觀察是否漏報或重複；停用後下一個通知不響 Junba。原日曆提示音可自行在 Google 日曆調整。
8. 測試停止、稍後提醒、5 秒測試及匯出讀回。確認備份沒有 API Key 或通知歷史文字。
9. 安裝前核對 APK 套件、版本、簽章；若不同簽章，不以自動解除安裝處理。固定 release 金鑰未設定時只能稱為 debug 測試版。
