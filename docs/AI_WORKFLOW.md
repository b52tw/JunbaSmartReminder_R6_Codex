# 說一句話，自動整理記事與鬧鐘

## 本輪修正

原 R6 的語音流程在 AI 解析後仍要求進入完整手動編輯器；AI 回傳的 `advanceMinutes` 與 `repeat` 沒有帶入，也沒有自動銜接原廠鬧鐘。預設模型名稱未經確認，模型查詢、測試連線與記事解析各自實作；逾時會被概括提示為檢查 Key。

現在首頁、記事與 AI 查詢頁共用兩個入口：

1. **語音交給 AI，自動整理記事／鬧鐘**：按鈕旁說明本次語音辨識文字會傳給 Gemini；使用者主動點選後，辨識結果直接交給 AI，不再多問一次要不要解析。
2. **輸入一句話，讓 AI 整理**：輸入後按送出才會傳給 Gemini。這也作為手機沒有語音辨識服務時的替代方式。

首次未設定 Key 時，可在當次流程加密儲存後繼續。模型會從該 Key 的 `models.list` 回覆挑選支援文字生成的模型，優先一般 Flash；已儲存模型回傳 404／410 時只進行一次模型重新查詢與替換。進階手動選模型仍保留，平常不必操作。

例如「明天下午兩點開會，提前三十分鐘提醒我」：AI 預覽應顯示活動時間 14:00、實際提醒 13:30，以及辨識出的重複規則。使用者按 **確認建立** 就儲存記事並處理所選的一種鬧鐘；不再強制進入日期、時間及提前分鐘的手動表單。只有需要更正時才開啟手動編輯器，且會保留 AI 提前分鐘與重複規則（含非預設的提前分鐘）。

## 原廠與 Junba 本機提醒

- 可用時預選原廠鬧鐘，使用 Android 公開 `ACTION_SET_ALARM`，帶入時、分、標籤、每日／每週規則及 `EXTRA_SKIP_UI=true`，請求時鐘直接建立。
- 這個旗標是請求，不保證 vivo 接受，也不能讀回原廠是否儲存成功；部分時鐘仍會顯示自己的畫面或選擇器。紀錄維持待核對，不能自動標記為本人已核對。
- 若時鐘無法開啟而拋出錯誤，記事先保留，改排 Junba 本機提醒並回報實際排程／權限狀態。成功開啟後若原廠拒絕或使用者取消，公開 API 無法確認，因此不會再偷偷加排另一個鬧鐘。
- 較遠日期、無法表達的開始日或每月規則會選擇 Junba 本機提醒，避免原廠提早響鈴或把每月改成單次。
- 正常流程只排所選的一種鬧鐘；原廠請求成功開啟時，記事的 `remind=false` 表示未另外排 Junba 鬧鐘，原廠請求狀態仍在連動紀錄。

## 逾時與草稿

使用者的截圖為 `SocketTimeoutException`。它表示連線或等待回應逾時，沒有證明 API Key 無效；雲端環境的連線狀況也不能代表手機網路。

現在會分別提示逾時、無法連線、安全連線、401／403 權限、429 配額、格式／內容不完整，並提供原要求直接重試。逾時與配額錯誤不會自動反覆送出或更換模型。原文、已解析預覽與草稿識別會保留在手機；重新開啟可繼續預覽，無須重新傳送。API Key 不放進提示詞、錯誤訊息或備份，只作 Gemini HTTPS 認證。

AI 時間不完整時只問缺少的問題；不虛構日期。日期不合法、提前提醒已過、重複規則不合法時，也不會靜默建立錯誤鬧鐘。使用者仍可明確選擇只存記事。

記事寫入與下一個 ID 在同一份 SharedPreferences 交易提交。每份 AI 草稿有獨立識別，重試儲存同一份已提交草稿不會再新增記事或再次送出原廠請求。只有儲存成功才清除對應 AI 草稿，舊請求也不能刪掉較新的草稿。關閉畫面後的過期網路回覆不會再開啟預覽。

## 自動驗證與限制

```bash
gradle --no-daemon --max-workers=2 assembleDebug assembleRelease testDebugUnitTest lintDebug
bash tools/test_native_alarm.sh
python3 tests/test_release_signing.py app/build/outputs/apk/release/app-release-unsigned.apk app/build/outputs/apk/debug/app-debug.apk -v
```

AI 的 38 項 JUnit 測試使用合成資料與模擬 API，涵蓋模型自動選用、分頁、模型失效替換上限、權限／配額不重試、逾時分類、日期／提前／重複、草稿重新開啟與過期回覆、空白記事、ID 避免碰撞及重複確認。沒有讀取使用者的 API Key、私人記事或日曆資料。

尚未使用實際 Gemini Key 連線、未跑語音服務或 vivo V2413／Android 16 真機。單元測試與建置成功不代表手機連線或原廠響鈴已修好；目前僅完成本機驗證，尚未合併到主分支、產生 Actions 附件或安裝到手機。更新仍須遵守 `APK_SIGNING.md` 的固定簽章與資料安全要求。

## vivo 真機驗證

1. 僅使用測試內容。儲存自己的 Key 後，不必先查模型，說「兩分鐘後提醒我喝水」，應直接出現 AI 預覽；確認一次後檢查原廠建立請求及實際響鈴。
2. 說「明天下午兩點開會，提前三十分鐘提醒，每週一次」，確認活動與提醒分別為 14:00／13:30，原廠的重複星期正確。
3. 說「每月十五日上午九點繳費」或較遠日期，應改選 Junba 本機提醒，不得把每月或日期丟失。
4. 說「明天提醒我」，應只詢問缺少的時間，補充後再整理。純記事不應被虛構成鬧鐘。
5. 關閉網路再試：出現連線錯誤時原文仍在，恢復網路可直接重試；切換 Wi-Fi／行動網路比較，不必重貼 Key。
6. 使用無效／無權限 Key 或達到配額時，顯示可區分的結果，不能宣稱排程成功。不要將 Key、錯誤中的私人內容貼到 Issues 或日誌。
7. 在 AI 處理中關閉或旋轉畫面，重新開啟能繼續草稿；不得因舊回覆覆寫新輸入。恢復同一已提交草稿不得新增第二份記事。
8. 不支援原廠自動建立時，確認時鐘畫面是否顯示；若取消，連動紀錄仍為待核對，不得宣稱已建立。測試結束後在原廠刪除測試鬧鐘。
