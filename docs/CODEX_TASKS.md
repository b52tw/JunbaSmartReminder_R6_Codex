# Codex 迭代工作清單（依風險排序）

## P0｜首先完成，否則不得執行會移除舊版的升級
1. 在 GitHub Actions 真正執行 Android `assembleDebug`；依錯誤修復語法／API／資源／Android 16 行為。交付可安裝 APK 與 CI logs。
2. 檢查目前匯出/匯入：`MainActivity.onActivityResult()` 匯入直接 `ReminderStore.save(this,notes)` 和 `NativeLinkStore.save(this,links)`；改為備份預覽、格式/欄位/ID 驗證、**合併不覆蓋**、衝突規則、事後比對筆數、排程恢復。
3. 設計跨 R3/R4/R5 到 R6 的資料格式遷移及多版本備份。確認歷史資料存在時才可說『已成功移轉』。舊版無法備份需阻止卸載、不能推測資料可救回。
4. 設定一致的 Release APK 簽章（存入 GitHub Actions secrets；不 commit keystore），制定首次 debug→release 過渡流程（可能須人工備份/卸載）。顯示簽章指紋與檢查方式。
5. 為 Windows 安裝／升級腳本實作**安全停機**：先檢查 ADB 裝置、找到正確 APK、核對 package/version/signing、完成資料備份＋驗證，使用者明確同意後才移除；失敗不刪原始備份。既有 R5 Windows 工具曾因 `$HOME` 命名衝突當場停止，不要複製同類 PowerShell 變數。

## P1｜主要功能
6. 讓語音文字輸入 → Gemini 解析 → 讓使用者預覽 → 建立記事、提醒／鬧鐘。Gemini 不可用時保留原始文字及草稿，使用者可選擇直接存記事。
7. 驗證空白標題/內容自動填「無訊息」，記事建立與通知/精確鬧鐘排程分離。提醒失敗必須保留記事、清楚提示重試。
8. Google 日曆：使用者選定帳號及日曆來源，既有及新增活動皆讀取明確的 reminder MINUTES（多組提醒、1 分鐘、30 分鐘、5 天），對時區/重複事件/取消/異動/去重/通知已過期做測試。
9. 本機 AlarmManager → 有聲前景服務：鎖屏、通知權限、精確鬧鐘、震動/音效、停止/貪睡、開機後重排程、vivo 省電背景限制測試。要誠實呈現它不是 vivo 原廠鬧鐘資料。

## P2｜使用體驗
10. 設定頁加入『備份、還原、匯入舊版、備份紀錄』及清楚的成功筆數/失敗筆數。
11. 顯示『記事已儲存』與『鬧鐘已成功排程』兩個**不同狀態**，不得只用單一成功提示。
12. 補齊『作者：峻爸』、繁體中文錯誤訊息、版本資訊。

## 完成定義
- CI build 成功，APK 實際產生且版本為 R6。
- 測試升級時舊記事/連動紀錄不減少且可復原；合併匯入不刪除新版資料。
- Gemini 異常不丟草稿；空白記事能保存。
- 已存在與新建 Google 日曆事件可正確建立 App 自有提醒。
- vivo V2413 Android 16 鎖定畫面實際響鈴、停止/稍後提醒測試有記錄。
- 未能寫入原廠時鐘則界面和文件明確說明限制。
